# CV Belgrano Web — Registro de trabajo

**Fecha:** 17 de noviembre de 2026

## 1. Tecnologías del proyecto

Se trabajó con:

- Laravel 13.17
- Livewire 4.1
- Livewire Blaze 1.0
- Livewire Flux 2.13.1
- Vite
- Tailwind CSS

## 2. Base de datos y Eloquent

Durante la jornada se completó el trabajo inicial de la estructura de datos.

### Migraciones
Se trabajó en las migraciones necesarias para la estructura de la aplicación.

### Modelos y relaciones
Se configuraron los modelos y sus relaciones Eloquent.

En el modelo `Cv.php` se incorporaron las relaciones:

- `education()`: relación con la formación educativa.
- `experiences()`: relación con las experiencias laborales.
- `skills()`: relación con las habilidades.
- Se mantuvieron `fillable` y `belongsTo(User::class)`.

### Factories y Seeder
Se trabajó en la generación de datos de prueba.

El seeder quedó configurado para generar:

- 1 usuario.
- 2 CV.
- 5 registros de educación por CV.
- 5 registros de experiencias por CV.
- 5 registros de habilidades por CV.

Se ejecutó:

```bash
php artisan db:seed
```

### Verificación
Se utilizaron Tinker y las relaciones `with()` para comprobar los datos y las consultas.

También se realizó una comparación del problema N+1 y el uso de carga anticipada de relaciones.

## 3. Estructura de páginas

Se comenzó a preparar la estructura visual de la aplicación.

Archivos trabajados:

- `resources/views/home.blade.php`
- `resources/views/pages/mis-perfiles.blade.php`

Se creó la vista principal `home.blade.php` y la página `mis-perfiles.blade.php`.

La página Mis Perfiles utiliza un componente SFC de Livewire 4:

```php
<?php

use Livewire\Component;

new class extends Component
{
    //
};
?>
```

También se incorporó contenido HTML para mostrar el título de la página.

## 4. Componentes y organización

Se comenzó a trabajar con la organización de componentes Blade y Livewire.

Se revisaron:

- La diferencia entre vistas y componentes.
- La ubicación de componentes dentro de `resources/views/components`.
- La organización mediante subcarpetas.
- La forma de invocar componentes Blade mediante etiquetas `<x-... />`.
- La diferencia entre `make:view` y `make:livewire`.

Se empezó a utilizar la estructura de layout:

`resources/views/components/layouts/layout.blade.php`

Se probó su invocación desde Mis Perfiles mediante:

```blade
<x-layouts.layout>
    ...
</x-layouts.layout>
```

También se revisó el uso de `x-slot` para enviar contenido al encabezado del layout.

## 5. CSS y Vite

Se creó el archivo:

`resources/css/home.css`

Se comprobó que los estilos se aplicaran correctamente desde la vista principal.

También se creó:

`resources/css/mis-perfiles.css`

Para cargar los estilos se utilizó:

```blade
@vite('resources/css/mis-perfiles.css')
```

Se revisó la configuración de `vite.config.js`, incluyendo:

- Laravel Vite Plugin.
- Tailwind CSS.
- Entrada de CSS y JavaScript.
- `refresh: true`.
- Configuración del servidor de desarrollo.

## 6. Servidores de desarrollo

Se trabajó con dos procesos:

```bash
npm run dev
```

Para ejecutar Vite.

```bash
php artisan serve
```

Para ejecutar el servidor de Laravel.

Se identificó una advertencia relacionada con el paquete opcional `fontaine`, utilizado para optimizar los fallbacks de fuentes. No se identificó como un error que impida ejecutar la aplicación.

## 7. Decisiones de arquitectura

Se definió avanzar primero con la estructura general de la aplicación:

1. Páginas.
2. Rutas.
3. Navegación.
4. Componentes.
5. CSS y diseño.
6. Funcionalidades.

El inicio de sesión no debe ser obligatorio para quienes solamente quieran crear y descargar un CV.

El registro o inicio de sesión se reservará para las funciones que necesiten guardar CV y trabajar con información asociada a una cuenta.

También se decidió quitar el dashboard inicial de Laravel y avanzar hacia páginas propias de la aplicación.
