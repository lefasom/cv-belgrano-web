## 1. `config()`: leer datos de la carpeta `config/`

Laravel lee **todos** los archivos de `config/` al arrancar. `config()` busca un valor ahí adentro.

```php
// config/app.php (ya viene con Laravel)
return [
    'name' => env('APP_NAME', 'Laravel'),
    'timezone' => 'UTC',
];
```

```php
config('app.name');              // 'Laravel'
config('app.timezone');          // 'UTC'
config('app.color', 'azul');     // 'azul' (no existe, devuelve el valor por defecto)
```

**Cómo se lee:** `config('archivo.clave.clave')`. Primero va el nombre del archivo sin `.php` y después las claves, separadas por puntos.

En JavaScript sería como tener un objeto grande y entrar con puntos:

```js
const config = { app: { name: 'Laravel', timezone: 'UTC' } };
config.app.name; // 'Laravel'
```

**`env()`** lee el archivo `.env`. Se usa **solo dentro de `config/`**; en el resto del código se usa `config()`.

```php
// .env
APP_NAME="CV Belgrano"

// config/app.php
'name' => env('APP_NAME', 'Laravel'),   // si no está en .env, 'Laravel'
```

> En este proyecto **no** usamos un archivo de config propio. Los datos fijos (lista de idiomas, URLs) están escritos en el archivo que los usa, como las constantes de la landing en React.

## 2. Funciones globales (*helpers*) contra clases

| Tipo | Ejemplos | ¿Lleva `use` arriba? |
|---|---|---|
| **Función global** | `config()`, `session()`, `route()`, `__()`, `asset()`, `url()` | **No.** Existen en todo el proyecto |
| **Clase** | `Livewire\Component`, `Livewire\Attributes\Session` | **Sí:** `use Livewire\Component;` |

- Las funciones globales están en `vendor/laravel/framework/src/Illuminate/Foundation/helpers.php`. Composer carga ese archivo solo.
- Es como `console.log()` o `fetch()` en JS: no se importan.

```php
route('crear');                 // '/crear' (la dirección de una ruta por su nombre)
asset('images/landing/x.png');  // la URL completa de un archivo en public/
session('idioma');              // lee algo de la sesión
session(['idioma' => 'pt']);    // guarda algo en la sesión
__('landing.hero.titulo');      // un texto traducido (ver punto 7)
```

## 4. Componentes: tres prefijos

| Prefijo | Qué es | Dónde vive |
|---|---|---|
| `<x-...>` | Componente **Blade**, sin estado | `resources/views/components/` |
| `<livewire:...>` | Componente **Livewire**, con estado | `resources/views/livewire/` (sin el ⚡) |
| sin prefijo | HTML común (`<button>`, `<input>`) | — |

El punto es la barra de carpeta: `<x-landing.captura>` es `components/landing/captura.blade.php`.

### Props (como las props de React)

```blade
{{-- components/saludo.blade.php --}}
@props([
    'nombre',            // obligatoria
    'grande' => false,   // con valor por defecto
])

<p @class(['texto-grande' => $grande])>Hola, {{ $nombre }}</p>
```

```blade
<x-saludo nombre="Ana" />                  {{-- texto fijo: sin dos puntos --}}
<x-saludo :nombre="$usuario->name" />      {{-- PHP: con dos puntos (como en Vue) --}}
<x-saludo nombre="Ana" grande />           {{-- booleano en true --}}
```

### Slots (como `children` en React)

```blade
{{-- components/tarjeta.blade.php --}}
<div class="tarjeta">
    <h2>{{ $titulo }}</h2>     {{-- slot con nombre --}}
    {{ $slot }}                {{-- slot por defecto = children --}}
</div>
```

```blade
<x-tarjeta>
    <x-slot:titulo>Mi título</x-slot:titulo>
    <p>Esto entra en $slot.</p>
</x-tarjeta>
```

Ejemplo real: el molde `layouts/app.blade.php` recibe cada página en `{{ $slot }}` y el CSS de esa página en `{{ $head }}`.

## 5. Estado en Livewire (como `useState`, pero en PHP)

```php
new class extends Component
{
    public bool $abierto = false;        // estado (useState(false))

    public function mount(): void        // corre una vez al crear el componente (useEffect con [])
    {
        //
    }

    public function alternar(): void     // una acción (como un onClick)
    {
        $this->abierto = ! $this->abierto;
    }
};
```

```blade
<button wire:click="alternar">Abrir</button>   {{-- onClick --}}

@if ($abierto)                                 {{-- {abierto && (...)} --}}
    <div class="modal">…</div>
@endif
```

| React | Livewire |
|---|---|
| `useState` | propiedad `public` |
| `useEffect(() => {}, [])` | `mount()` |
| `onClick={fn}` | `wire:click="fn"` |
| `value` + `onChange` | `wire:model="campo"` |
| `onSubmit` | `<form wire:submit="guardar">` |
| `.map()` con `key` | `@foreach` con `wire:key` |
| un "cargando…" manual | `wire:loading` / `wire:loading.remove` |

**El truco del borrador** (lo usan los cuatro modales de `/crear`):
1. `abrir()` copia lo guardado a `$borrador` y pone `$abierto = true`.
2. Los inputs editan el borrador: `wire:model="borrador.full_name"`.
3. **Guardar** valida, copia `$borrador` a lo guardado y cierra el modal.
4. **Cancelar** o la **×** solo cierran. Lo guardado no cambia.

**Validar y mostrar errores:**

```php
$this->validate(
    ['borrador.email' => 'required|email'],
    ['borrador.email.required' => 'Poné tu correo.']
);
```

```blade
@error('borrador.email') <p class="error">{{ $message }}</p> @enderror
```

## 6. La sesión: el "contexto" de Laravel

En React el estado vive en el navegador mientras la página está abierta. En Laravel, **cada página es un pedido nuevo**, y PHP se olvida de todo cuando termina de responder. Lo que tiene que sobrevivir entre páginas va a la **sesión**:

```text
NAVEGADOR                         SERVIDOR
cookie: id = "a8f3…" ──────────►  sesión "a8f3…" = { idioma: 'pt', cv: {...} }
(solo un número)                  (los datos están acá, no en el navegador)
```

- **Con Livewire:** `#[Session]` arriba de una propiedad la guarda y la recupera sola.

  ```php
  use Livewire\Attributes\Session;   // es de Livewire, no una librería aparte

  #[Session]
  public array $habilidades = [];
  ```

- **A mano:** `session(['idioma' => 'pt'])` para guardar y `session('idioma')` para leer.
- **Dónde se guarda:** `SESSION_DRIVER=file` en `.env` la guarda en `storage/framework/sessions`. Con `database` iría a la tabla `sessions` de MySQL.
- **Cuánto dura:** `SESSION_LIFETIME=120` (minutos sin uso).

| React | Laravel |
|---|---|
| Context para "quién está logueado" | `auth()->user()` o `@auth` (ya viene) |
| Context para datos que se arman entre pantallas | la sesión (`#[Session]`) |
| props y callbacks dentro de una pantalla | props (`:cv=`) y eventos (`dispatch` / `#[On]`) |

## 7. Traducciones (`lang/`)

Un archivo por idioma, con la misma forma:

```php
// lang/es/landing.php
return ['hero' => ['titulo' => 'Armá un CV que te represente']];

// lang/en/landing.php
return ['hero' => ['titulo' => 'Build a résumé that represents you']];
```

```blade
{{ __('landing.hero.titulo') }}      {{-- archivo.clave.clave, igual que config() --}}
@php($t = __('landing'))             {{-- todo el archivo como array --}}
{{ $t['hero']['titulo'] }}
```

`__()` usa el idioma actual de la app (`app()->getLocale()`). El idioma lo elige el middleware del punto 8.

## 8. Middleware: código que corre antes de cada página

`app/Http/Middleware/ElegirIdioma.php`:

```php
public function handle(Request $request, Closure $next): Response
{
    $disponibles = ['es', 'en', 'pt'];
    $idioma = $request->session()->get('idioma');          // 1. ¿lo eligió con el selector?

    if (! in_array($idioma, $disponibles, true)) {
        $idioma = $request->getPreferredLanguage($disponibles) ?? 'es';   // 2. si no, el del navegador
    }

    app()->setLocale($idioma);
    return $next($request);                                 // sigue hacia la página
}
```

Se registra en `bootstrap/app.php`, dentro del grupo `web` (todas las páginas):

```php
$middleware->web(append: [\App\Http\Middleware\ElegirIdioma::class]);
```

Es parecido a un *middleware* de Express: recibe el pedido, hace algo y llama a `next`. Otro middleware que ya usamos es `auth`: si no estás logueado, te manda al login.

**El selector** (`livewire/idioma.blade.php`) tiene el estado `$abierto` para el menú y `cambiar('pt')`, que hace `session(['idioma' => 'pt'])` y recarga la página. Al recargar, el middleware ve `'pt'` en la sesión.

## 9. CSS con Vite

- **Un CSS por componente.** Cada componente lo carga con `@vite` adentro:

  ```blade
  @vite('resources/css/landing/volver-arriba.css')
  ```

- **Todo archivo que se carga con `@vite`** tiene que estar en la lista `input` de `vite.config.js`. Si falta, falla con *"Unable to locate file in Vite manifest"*.
- `npm run dev` sirve los archivos mientras trabajás (y recarga sola). `npm run build` arma la versión final en `public/build`, que es la que usan las pruebas.
- **Si cambia `vite.config.js`**, hay que reiniciar `npm run dev`.
- **El botón de volver arriba** aparece al bajar sin JavaScript, con `animation-timeline: scroll()`.

## 10. Decisiones del día

| Decisión | Por qué |
|---|---|
| Sin Flux ni Tailwind (desinstalados) | Aprender Livewire "en crudo" y escribir el CSS propio |
| Se borraron los ajustes del kit (perfil, contraseña, apariencia) | Estaban hechos con Flux; queda registro, login, logout y recuperar contraseña |
| Home = landing; `/crear` = creador | La web es vidriera de la app y el creador se prueba sin cuenta |
| Se quitó Mis perfiles | Ya cumplió su función; después del login se va a `/crear` |
| Componentes Livewire sin ⚡, en `resources/views/livewire/` | Convención elegida |
| Sesión en archivos (`SESSION_DRIVER=file`) | Persistencia de verdad sin base de datos |
| Datos fijos escritos en el archivo que los usa (no `config/` propio) | Más parecido a cómo se hace en la landing de React |
