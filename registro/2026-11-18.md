## 1. `config()`: leer datos de la carpeta `config/`

Laravel lee **todos** los archivos de `config/` al arrancar. `config()` busca un valor ahí adentro.

```php
// config/app.php (ya viene con Laravel)
return [
    'name' => env('APP_NAME', 'Laravel'),
    'timezone' => 'UTC',
];
```

```php
config('app.name');              // 'Laravel'
config('app.timezone');          // 'UTC'
config('app.color', 'azul');     // 'azul' (no existe, devuelve el valor por defecto)
```

**Cómo se lee:** `config('archivo.clave.clave')`. Primero va el nombre del archivo sin `.php` y después las claves, separadas por puntos.

En JavaScript sería como tener un objeto grande y entrar con puntos:

```js
const config = { app: { name: 'Laravel', timezone: 'UTC' } };
config.app.name; // 'Laravel'
```

**`env()`** lee el archivo `.env`. Se usa **solo dentro de `config/`**; en el resto del código se usa `config()`.

```php
// .env
APP_NAME="CV Belgrano"

// config/app.php
'name' => env('APP_NAME', 'Laravel'),   // si no está en .env, 'Laravel'
```

> En este proyecto **no** usamos un archivo de config propio. Los datos fijos (lista de idiomas, URLs) están escritos en el archivo que los usa, como las constantes de la landing en React.

## 4. Componentes: tres prefijos

| Prefijo | Qué es | Dónde vive |
|---|---|---|
| `<x-...>` | Componente **Blade**, sin estado | `resources/views/components/` |
| `<livewire:...>` | Componente **Livewire**, con estado | `resources/views/livewire/` (sin el ⚡) |
| sin prefijo | HTML común (`<button>`, `<input>`) | — |

El punto es la barra de carpeta: `<x-landing.captura>` es `components/landing/captura.blade.php`.

### Props (como las props de React)

```blade
{{-- components/saludo.blade.php --}}
@props([
    'nombre',            // obligatoria
    'grande' => false,   // con valor por defecto
])

<p @class(['texto-grande' => $grande])>Hola, {{ $nombre }}</p>
```

```blade
<x-saludo nombre="Ana" />                  {{-- texto fijo: sin dos puntos --}}
<x-saludo :nombre="$usuario->name" />      {{-- PHP: con dos puntos (como en Vue) --}}
<x-saludo nombre="Ana" grande />           {{-- booleano en true --}}
```

### Slots (como `children` en React)

```blade
{{-- components/tarjeta.blade.php --}}
<div class="tarjeta">
    <h2>{{ $titulo }}</h2>     {{-- slot con nombre --}}
    {{ $slot }}                {{-- slot por defecto = children --}}
</div>
```

```blade
<x-tarjeta>
    <x-slot:titulo>Mi título</x-slot:titulo>
    <p>Esto entra en $slot.</p>
</x-tarjeta>
```

Ejemplo real: el molde `layouts/app.blade.php` recibe cada página en `{{ $slot }}` y el CSS de esa página en `{{ $head }}`.

## 5. Estado en Livewire (como `useState`, pero en PHP)

```php
new class extends Component
{
    public bool $abierto = false;        // estado (useState(false))

    public function mount(): void        // corre una vez al crear el componente (useEffect con [])
    {
        //
    }

    public function alternar(): void     // una acción (como un onClick)
    {
        $this->abierto = ! $this->abierto;
    }
};
```

```blade
<button wire:click="alternar">Abrir</button>   {{-- onClick --}}

@if ($abierto)                                 {{-- {abierto && (...)} --}}
    <div class="modal">…</div>
@endif
```

| React | Livewire |
|---|---|
| `useState` | propiedad `public` |
| `useEffect(() => {}, [])` | `mount()` |
| `onClick={fn}` | `wire:click="fn"` |
| `value` + `onChange` | `wire:model="campo"` |
| `onSubmit` | `<form wire:submit="guardar">` |
| `.map()` con `key` | `@foreach` con `wire:key` |
| un "cargando…" manual | `wire:loading` / `wire:loading.remove` |

**El truco del borrador** (lo usan los cuatro modales de `/crear`):
1. `abrir()` copia lo guardado a `$borrador` y pone `$abierto = true`.
2. Los inputs editan el borrador: `wire:model="borrador.full_name"`.
3. **Guardar** valida, copia `$borrador` a lo guardado y cierra el modal.
4. **Cancelar** o la **×** solo cierran. Lo guardado no cambia.

**Validar y mostrar errores:**

```php
$this->validate(
    ['borrador.email' => 'required|email'],
    ['borrador.email.required' => 'Poné tu correo.']
);
```

```blade
@error('borrador.email') <p class="error">{{ $message }}</p> @enderror
```

## 6. La sesión: el "contexto" de Laravel

En React el estado vive en el navegador mientras la página está abierta. En Laravel, **cada página es un pedido nuevo**, y PHP se olvida de todo cuando termina de responder. Lo que tiene que sobrevivir entre páginas va a la **sesión**:

```text
NAVEGADOR                         SERVIDOR
cookie: id = "a8f3…" ──────────►  sesión "a8f3…" = { idioma: 'pt', cv: {...} }
(solo un número)                  (los datos están acá, no en el navegador)
```

- **Con Livewire:** `#[Session]` arriba de una propiedad la guarda y la recupera sola.

  ```php
  use Livewire\Attributes\Session;   // es de Livewire, no una librería aparte

  #[Session]
  public array $habilidades = [];
  ```

- **A mano:** `session(['idioma' => 'pt'])` para guardar y `session('idioma')` para leer.
- **Dónde se guarda:** `SESSION_DRIVER=file` en `.env` la guarda en `storage/framework/sessions`. Con `database` iría a la tabla `sessions` de MySQL.
- **Cuánto dura:** `SESSION_LIFETIME=120` (minutos sin uso).

| React | Laravel |
|---|---|
| Context para "quién está logueado" | `auth()->user()` o `@auth` (ya viene) |
| Context para datos que se arman entre pantallas | la sesión (`#[Session]`) |
| props y callbacks dentro de una pantalla | props (`:cv=`) y eventos (`dispatch` / `#[On]`) |

## 8. Middleware: código que corre antes de cada página

`app/Http/Middleware/ElegirIdioma.php`:

```php
public function handle(Request $request, Closure $next): Response
{
    $disponibles = ['es', 'en', 'pt'];
    $idioma = $request->session()->get('idioma');          // 1. ¿lo eligió con el selector?

    if (! in_array($idioma, $disponibles, true)) {
        $idioma = $request->getPreferredLanguage($disponibles) ?? 'es';   // 2. si no, el del navegador
    }

    app()->setLocale($idioma);
    return $next($request);                                 // sigue hacia la página
}
```

Se registra en `bootstrap/app.php`, dentro del grupo `web` (todas las páginas):

```php
$middleware->web(append: [\App\Http\Middleware\ElegirIdioma::class]);
```

Es parecido a un *middleware* de Express: recibe el pedido, hace algo y llama a `next`. Otro middleware que ya usamos es `auth`: si no estás logueado, te manda al login.

**El selector** (`livewire/idioma.blade.php`) tiene el estado `$abierto` para el menú y `cambiar('pt')`, que hace `session(['idioma' => 'pt'])` y recarga la página. Al recargar, el middleware ve `'pt'` en la sesión.

## 9. CSS con Vite

- **Un CSS por componente.** Cada componente lo carga con `@vite` adentro:

  ```blade
  @vite('resources/css/landing/volver-arriba.css')
  ```

- **Todo archivo que se carga con `@vite`** tiene que estar en la lista `input` de `vite.config.js`. Si falta, falla con *"Unable to locate file in Vite manifest"*.
- `npm run dev` sirve los archivos mientras trabajás (y recarga sola). `npm run build` arma la versión final en `public/build`, que es la que usan las pruebas.
- **Si cambia `vite.config.js`**, hay que reiniciar `npm run dev`.
- **El botón de volver arriba** aparece al bajar sin JavaScript, con `animation-timeline: scroll()`.

## 11. Diccionario de etiquetas: qué es cada cosa y por qué se escribe así

### 11.1 Lo básico de Blade

| Se escribe | Qué hace | En React |
|---|---|---|
| `{{ $nombre }}` | Muestra un valor. **Lo escapa**: si trae `<script>`, lo muestra como texto y no lo ejecuta | `{nombre}` |
| `{!! $html !!}` | Muestra sin escapar. Solo con HTML en el que confiás | `dangerouslySetInnerHTML` |
| `{{-- comentario --}}` | Comentario de Blade. **No llega al navegador** (`<!-- -->` sí llega) | `{/* comentario */}` |
| `@php($x = 5)` | Una línea de PHP dentro de la vista | `const x = 5;` arriba del componente |
| `@php ... @endphp` | Varias líneas de PHP | — |

**¿Por qué tantas `@`?** La `@` le avisa a Blade "esto es una instrucción, no texto". Blade convierte cada `@algo` en PHP antes de mostrar la página. Por ejemplo, `@if ($x)` se convierte en `<?php if ($x): ?>`.

### 11.2 Condiciones y listas

```blade
@if ($abierto)
    …
@elseif ($otro)
    …
@else
    …
@endif

@foreach ($habilidades as $i => $habilidad)
    {{ $loop->iteration }}   {{-- 1, 2, 3… (número de vuelta, empieza en 1) --}}
    {{ $loop->index }}       {{-- 0, 1, 2… (empieza en 0) --}}
    {{ $loop->first }}       {{-- true en la primera vuelta --}}
    {{ $loop->last }}        {{-- true en la última --}}
@endforeach

@switch($nombre)
    @case('globo') … @break
    @case('corona') … @break
@endswitch
```

- `$loop` lo crea Blade solo dentro de cada `@foreach`. En React lo hacías con el segundo parámetro de `.map((item, i) => …)`.
- `@switch` es el `switch` de JS. Lo usa `components/landing/icono.blade.php` para elegir el SVG.

### 11.3 Atajos que ya vienen

| Se escribe | Qué hace |
|---|---|
| `@auth … @else … @endauth` | Muestra una parte si hay alguien logueado y otra si no. Es lo de `AuthContext`, sin escribirlo |
| `@csrf` | Agrega un campo oculto con un código de seguridad. **Todo `<form method="POST">` lo necesita**: Laravel rechaza el POST si no lo trae (error 419). Evita que otra página mande formularios en tu nombre |
| `@error('email') {{ $message }} @enderror` | Si la validación falló en ese campo, muestra el mensaje. `$message` lo crea Blade solo |
| `@checked(old('remember'))` | Escribe `checked` si la condición es verdadera. `old('campo')` es lo que el usuario había escrito antes de un error |
| `@vite('archivo.css')` | Pone la etiqueta `<link>` (o `<script>`) correcta. Con `npm run dev` apunta al servidor de Vite; con `npm run build`, al archivo final de `public/build` |

### 11.4 `@class`: clases según condiciones

```blade
<ul @class(['landing-lista', 'landing-lista-chica' => $chica])>
```

- Lo que **no tiene flecha** va siempre: `landing-lista`.
- Lo que **tiene flecha** va solo si la condición es verdadera: `landing-lista-chica` solo si `$chica` es `true`.
- Resultado: `class="landing-lista landing-lista-chica"` o `class="landing-lista"`.

**¿Por qué así y no armando el texto a mano?** Porque es lo mismo que la librería `clsx` (o `classnames`) en React, y se evitan espacios de más y condiciones metidas en el medio del texto:

```jsx
// React
<ul className={clsx('landing-lista', { 'landing-lista-chica': chica })}>
```

### 11.5 ¿Por qué `x-`? Componentes Blade

`x-` es el prefijo que eligió Laravel para decir **"esto es un componente mío, no una etiqueta de HTML"**. Sin el prefijo, Blade no puede distinguir `<boton>` (que podría ser HTML) de tu componente.

```text
<x-landing.captura />
  │ └──┬──┘ └──┬──┘
  │  carpeta  archivo      →  resources/views/components/landing/captura.blade.php
  └─ "es un componente Blade"
```

El **punto** separa carpetas: `x-landing.captura` es `components/landing/captura.blade.php`. En React era `import Captura from './landing/Captura'`, y acá se encuentra solo por el nombre.

### 11.6 `@props`: las props que recibe un componente

```blade
{{-- components/landing/boton.blade.php --}}
@props([
    'texto',               // obligatoria (sin valor por defecto)
    'detalle' => null,     // opcional
    'externo' => true,     // opcional, true por defecto
])
```

Es como la desestructuración de React: `function Boton({ texto, detalle = null, externo = true })`.

### 11.7 Pasar props: con `:` o sin `:`

```blade
<x-landing.boton texto="Crear mi CV" />                   {{-- sin ":"  → texto fijo  --}}
<x-landing.boton :texto="__('landing.web.boton')" />      {{-- con ":"  → código PHP  --}}
<x-landing.boton :url="route('crear')" :externo="false" />
<x-landing.lista :items="$datos['lista']" chica />        {{-- sin valor → true      --}}
<x-landing.seccion-panel id-seccion="ia" />               {{-- id-seccion llega como $idSeccion --}}
```

| Blade | React |
|---|---|
| `texto="Hola"` | `texto="Hola"` |
| `:texto="$variable"` | `texto={variable}` |
| `:externo="false"` | `externo={false}` |
| `chica` | `chica` (= `true`) |

**Ojo:** `externo="false"` sin dos puntos manda el **texto** `"false"`, y un texto no vacío cuenta como verdadero. Para booleanos y números, siempre `:`.

### 11.8 `$attributes`: lo que no es prop

Lo que le pasás a un componente y **no está en `@props`** (por ejemplo `class`) queda en `$attributes`:

```blade
{{-- components/landing/boton.blade.php --}}
<a href="{{ $url }}" {{ $attributes->merge(['class' => 'landing-boton']) }}>
```

```blade
<x-landing.boton :url="$urlApk" texto="APK" class="landing-boton-secundario" />
{{-- resultado: class="landing-boton landing-boton-secundario" --}}
```

`merge` **suma** las clases: la del componente más la que le pasaste. En React era recibir `className` y sumarlo a la clase propia.

### 11.9 Slots: `$slot` y `<x-slot:nombre>`

**`$slot` = `children`.** Todo lo que ponés entre la etiqueta de apertura y la de cierre:

```blade
<x-landing.seccion-panel :datos="$t['ia']" id="landing-ia-titulo">
    <div class="landing-ia-tarjetas">…</div>     {{-- esto llega como $slot --}}
</x-landing.seccion-panel>
```

**`<x-slot:nombre>` = un hueco con nombre.** Cuando un componente tiene **más de un lugar** donde meter contenido:

```blade
<x-landing.seccion-panel …>
    <x-slot:etiqueta>                             {{-- llega como $etiqueta --}}
        <span class="landing-etiqueta landing-etiqueta-dorada">…</span>
    </x-slot:etiqueta>

    <div class="landing-ia-tarjetas">…</div>      {{-- llega como $slot --}}
</x-landing.seccion-panel>
```

En React lo hacías con una prop que recibe JSX:

```jsx
<SeccionPanel etiqueta={<span className="…">…</span>}>
  <div className="landing-ia-tarjetas">…</div>
</SeccionPanel>
```

Dentro del componente:

```blade
@if (isset($etiqueta))            {{-- ¿me mandaron el slot "etiqueta"? --}}
    {{ $etiqueta }}
@endif

@if ($slot->isNotEmpty())         {{-- ¿me mandaron children? --}}
    {{ $slot }}
@endif
```

### 11.10 `<x-slot:head>`: por qué el `@vite` va "encerrado"

```blade
<x-layouts::app title="Crear CV">
    <x-slot:head>
        @vite('resources/css/crear.css')
    </x-slot:head>

    <h1>…</h1>      {{-- esto va al $slot (dentro de <main>) --}}
</x-layouts::app>
```

El molde tiene **dos huecos** en lugares distintos de la página:

```blade
{{-- layouts/app.blade.php --}}
<head>
    @vite('resources/css/layout.css')
    {{ $head ?? '' }}          ← acá entra lo de <x-slot:head>
</head>
<body>
    <main>
        {{ $slot }}            ← acá entra todo lo demás
    </main>
</body>
```

**¿Por qué?** Porque el CSS de la página tiene que ir en el `<head>`, y el contenido va en el `<body>`. Si el `@vite` quedara suelto, caería en el `$slot`, o sea en el `<body>`. Funcionaría, pero el navegador podría mostrar la página un instante sin estilos.

`{{ $head ?? '' }}` significa "si la página mandó un `head`, ponelo; si no, nada". `??` es igual que en JS.

> Los componentes Livewire de `/crear` sí cargan su CSS con `@vite` adentro del propio componente (en el `<body>`), porque no pueden meter nada en el `<head>` del molde. Es la forma más simple de que cada componente tenga su CSS.

### 11.11 `<x-layouts::app title="Crear CV">`: el molde y su título

```text
<x-layouts::app  title="Crear CV" :menu="false">
    └──┬──┘  └┬┘
  espacio  archivo    →  resources/views/layouts/app.blade.php
  de nombres
```

- **`::` (dos puntos dobles)** es un **espacio de nombres**: "buscalo en la carpeta registrada como `layouts`". Esa carpeta la registra Livewire (en su configuración, `'layouts' => resources/views/layouts`). Así el molde no tiene que estar en `components/`.
  - Con un punto, `<x-layouts.app>`, buscaría `components/layouts/app.blade.php`.
  - Con `::`, `<x-layouts::app>`, busca `layouts/app.blade.php`.
- **`title`** es una prop del molde:

  ```blade
  @props([
      'title' => null,
      'menu' => true,
  ])

  <title>{{ filled($title) ? $title.' - '.config('app.name') : config('app.name') }}</title>
  ```

  Es **el texto de la pestaña del navegador**. Con `title="Crear CV"` la pestaña dice "Crear CV - CV Belgrano". Sin `title`, solo "CV Belgrano". `filled()` es una función global que devuelve `true` si el valor no está vacío.
- **`:menu="false"`** le dice al molde que no muestre su menú (la home trae la barra de la landing).
- **¿Por qué las páginas Livewire no lo escriben?** Livewire busca **por defecto** el molde `layouts::app` y mete la página ahí solo.

### 11.12 `<livewire:...>`: componentes con estado

```blade
<livewire:creador.datos />     →  resources/views/livewire/creador/datos.blade.php
<livewire:idioma />            →  resources/views/livewire/idioma.blade.php
```

Igual que con `x-`, el punto es la barra de carpeta. Se escribe distinto (`livewire:` y no `x-`) porque **no es lo mismo**:

| | `<x-...>` Blade | `<livewire:...>` Livewire |
|---|---|---|
| ¿Tiene estado? | No | Sí (propiedades `public`) |
| ¿Cuándo se dibuja? | Una vez, al armar la página | Al armar la página **y** cada vez que cambia su estado |
| ¿Puede responder a clics? | No (solo HTML) | Sí, con `wire:` |

**Una regla de Livewire:** la vista de un componente Livewire tiene que tener **un solo elemento raíz** (un `<div>` que envuelva todo). Por eso cada componente del creador empieza con `<div class="seccion …">` y termina con `</div>`.

### 11.13 `wire:`: lo que conecta el HTML con la clase PHP

`wire:` es el prefijo de Livewire, igual que `v-` en Vue. Cada atributo `wire:` le dice al JS de Livewire "cuando pase tal cosa, avisale al servidor".

| Atributo | Qué hace | En React |
|---|---|---|
| `wire:click="abrir"` | Al hacer clic, ejecuta `abrir()` en el servidor y redibuja el componente | `onClick={abrir}` |
| `wire:click="cambiar('pt')"` | Igual, pasando un parámetro | `onClick={() => cambiar('pt')}` |
| `wire:model="borrador.email"` | Une el input con la propiedad `$borrador['email']`. El valor se manda **cuando hay una acción** (por ejemplo, al guardar), no en cada tecla | `value` + `onChange` |
| `wire:model.live="buscar"` | Igual, pero se manda **mientras escribís** | `onChange` que actualiza en cada tecla |
| `wire:submit="guardar"` | Al enviar el formulario, ejecuta `guardar()` **sin recargar la página** | `onSubmit` con `e.preventDefault()` |
| `wire:key="habilidad-{{ $i }}"` | Identifica cada fila de un `@foreach` para no mezclarlas al redibujar | `key={i}` |
| `wire:loading` | El elemento aparece **solo mientras** el servidor responde | `{cargando && <span>…</span>}` |
| `wire:loading.remove` | El elemento **desaparece** mientras el servidor responde | `{!cargando && <span>…</span>}` |
| `wire:loading.attr="disabled"` | Mientras responde, agrega el atributo `disabled` (no se puede tocar dos veces) | `disabled={cargando}` |
| `wire:target="guardar"` | Hace que el `wire:loading` reaccione **solo** a `guardar()` y no a cualquier acción | — |

**El botón Guardar, armado con todo esto:**

```blade
<button type="submit" class="boton" wire:loading.attr="disabled" wire:target="guardar">
    <span wire:loading.remove wire:target="guardar">Guardar</span>
    <span wire:loading wire:target="guardar">Guardando…</span>
</button>
```

1. En reposo: se ve "Guardar".
2. Al tocarlo: el `<form wire:submit="guardar">` llama a `guardar()`. Mientras el servidor responde, el botón queda deshabilitado y se ve "Guardando…".
3. Cuando el servidor responde, Livewire redibuja: el modal se cierra (`$abierto = false`) y aparece el mensaje.

### 11.14 La parte de arriba de un componente Livewire

```php
<?php

use Livewire\Attributes\Session;   // importa una clase (como import en JS)
use Livewire\Component;

new class extends Component        // una clase sin nombre que hereda de Component
{
    #[Session]                     // un "atributo": una etiqueta que le agrega comportamiento
    public array $habilidades = [];
    …
};
?>

<div>…la vista…</div>
```

- **`new class extends Component`** crea una clase sin nombre. Livewire 4 permite tener la clase y la vista **en el mismo archivo** (componente de un solo archivo). El nombre del componente sale del nombre del archivo.
- **`#[Session]`** es un **atributo de PHP**: una etiqueta que se pone arriba de algo para darle un comportamiento extra. Es parecido a los decoradores de TypeScript o de NestJS (`@Session()`).
- **`?>`** cierra el PHP. Lo que sigue es la vista (Blade).
